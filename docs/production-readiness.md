# Spanvision Infra production readiness

Updated: 6 October 2026. This is a working audit of the website and Windows applications. It records verified behavior and remaining release gates. Passing a build or test suite does not establish that every button, file format, installer or engineering calculation is correct.

The entire suite is **not yet approved for a production release**. Source fixes described here have not yet been pushed or deployed. The existing Vercel and Render deployments are the previous release. The public availability indicator means a tool can open; it is not a production certification.

The requested engineering coverage is India, United States and United Kingdom. See [engineering standards and verification](engineering-standards.md). These code families are additional release requirements; existing Dutch Eurocode results do not establish that coverage.

## Defects repaired

- Calc and PDF presentation translation had changed internal format/operator codes. Restored the original domain identifiers while retaining English presentation.
- BIM validation now preserves asynchronous job contracts, accepts multipart and legacy query standards, returns clear errors for unsupported IFC XML and unknown standards, supports bounded IFC ZIP input, and stores visitor filenames as metadata rather than filesystem paths.
- BIM cloud geometry runs in an isolated process with timeout/crash reporting and one native geometry worker at a time. A failed native conversion cannot terminate the HTTP process.
- Cloud request limits count actual streamed bytes, including missing or dishonest Content-Length headers. Workspaces remain private anonymous sessions.
- Frame browser operations now call real Rust domain functions or persist project data instead of returning empty demonstrations. Oversized cutting pieces are rejected; stock, saw kerf and remaining length are checked together.
- Pointcloud imports reject non-finite coordinates and truncated scan structures. Bounds cover every point. PTX registration and byte RGB channels follow the Cyclone format.
- The main hub performs actual local OCR and emits text and searchable PDFs. Its profile persists locally without credentials.
- Calc uses updated PDF.js and the official SheetJS distribution. PDF worker bundling, first-page canvas initialization and measurement units across zoom levels are repaired and verified with an actual browser PDF workflow.
- Planner verification repairs preserve the original numeric and oracle baselines. Windows source line endings and gzip OS headers are normalized deterministically; frozen reference-manifest content is restored.
- FEM root development, build and preview commands now use the canonical v2 application. Native export-binding tests run serially to prevent concurrent writes to generated TypeScript files on Windows; the complete native gate passes without changing numerical assertions.
- New FEM projects use English default load-case names. Existing saved project names and load-case IDs are preserved; the numeric self-weight regression still passes all 110 checks.
- Planner rejects a blocked automatic-WBS cell before building unnecessary calendar/projected-task state. Its 2,000-row benchmark passes the unchanged 3,000 ms limit at a median 58.4 ms; all 178 transaction checks pass. The full release gate still needs a passing rerun; the 06:57–07:16 UTC attempt returned planning exit 1 despite 560/560 scheduling cases and all five timezone runs passing. A diagnostic rerun is tracing the failed command without relaxing any checks.
- The main preview now forwards FEM calculation requests to the real local Rust API, with an explicit service-unavailable error when the API cannot be reached. Browser verification passes through the main preview port as well as the standalone preview.
- 2D CAD's CSS reset now participates in the base cascade layer so it cannot erase editor spacing after the Tailwind upgrade. The vendored upstream browser SQL distribution preserves its MIT license and provenance while removing unused native mobile dependencies.
- Pointcloud exports restore original survey offsets and axes. PLY retains double coordinates, triangle connectivity and classifications; CSV uses its named columns instead of guessing their order. LAS/LAZ bounds include every source point and legacy classification flags are separated from classification codes.
- Native Pointcloud export now reads the complete source rather than relying on the displayed octree or browser-only data store. It protects the source and replaces the destination only after writing successfully. Malformed LAS metadata and zero-size batches are rejected. The local automation bridge rejects browser origins and unrelated Host headers and limits actual streamed script bytes.
- Pointcloud edits use survey X/Y/Z axes and update exported bounds. Invalid or overflowing transforms preserve the previous data. Mesh thinning rejects removal that would leave invalid face indices; reflected scaling retains face winding. Native octree display and camera queries now use the same handedness as browser geometry. Native editing/reconstruction can prepare a complete source of up to one million points and 128 MB; larger sources remain available for native viewing and complete-source export.
- Geotechnical PDF page selection reuses one document/worker and cancels rendering and destroys the worker on close or replacement. PDF cancel and invalid input preserve the existing site-plan overlay. Missing site-plan ribbon translations are supplied in the English resource without changing domain identifiers.
- IFC sequence imports stage geometry before replacing a document, preserving the active view after an invalid second import. Playback controls share one timer, clearing a parameter stops stale playback, and parameter CSV exports escape spreadsheet formulas. The file chooser now supports keyboard activation and retrying the same file.
- The new international steel tension sheet uses the selected method independently of Dutch project factors. Displayed results are rounded for readability; machine-readable report evidence preserves full precision, method/edition, units, inputs and exclusions. Incorrectly parsed explanatory text in the new template was repaired.
- PDF Studio removes a failed new-file tab, releases its loading task and restores the previously active document. The loading overlay clears; valid retry, saved annotations and a non-adjacent previous tab are verified in the real browser.
- Field Workspace validates imported project collections before changing the active project. Invalid JSON, incorrect collection types and null entries show an error and preserve existing data. A rendering failure restores the previous project; file-read failures also display an error.

## Release blockers

1. Complete and verify remaining sample-only, unsupported and incomplete workflows. Do not report success for a no-op action or replace a missing calculation with a fabricated result.
2. Extend acceptance beyond the newly deployed canonical FEM frontend and real Rust bridge. Live API and theme checks pass; representative engineering workflows and Windows package acceptance remain required.
3. Run representative import/edit/save/reopen/export workflows and inspect output files. Button clicks and TypeScript checks alone are insufficient.
4. Build and test Windows installers, upgrades, uninstall, recovery and first-use dependencies. Native UI acceptance has not been performed in this environment.
5. Resolve dependency vulnerabilities and complete licensing/attribution, especially new OCR and speech-model dependencies.
6. Establish the intended hosting capacity, monitoring, backup and support arrangements. Current Render services use temporary storage and can sleep; they are unsuitable for durable project storage or a guaranteed availability commitment.

The release decision remains pending. No zero-bug claim is made.

### Frame file and geometry verification update

The updated native core passes 132 tests. The browser uses the same Rust IFC parser and exporter as native file operations. A real door export passes independent IfcOpenShell schema, EXPRESS and meshing checks: LOD 200 has one solid, LOD 300 has two and LOD 400 has five modeled solids. Height follows world Z and depth follows world Y. Imports retain window/door identity and supplied overall dimensions; they do not reconstruct arbitrary IFC placement, profiles, fittings or fabrication data. Non-rectangular detailed exports report their unsupported scope rather than substituting rectangular detail. The LOD 400 duplication defect is repaired, but this does not establish complete fabrication output.

Actual browser tests verify complete `.ofs` downloads and reopening, rejection of corrupt files without data loss, custom-profile updates without duplicates, and Save/Discard/Cancel for project and working-profile edits. Production CSV files download in one ZIP; Python independently verifies CRCs, column structure and reference cut lengths. The actual Frame DXF opens in 2D CAD with correct text scale, fits the canvas in both themes, and survives save/reopen with all 12 entities. The exported GLB passes the Khronos validator with zero errors and warnings.

The user selected generic CNC preview output until a machine/controller is specified. Every `.nc` file states that it is unverified and that tenon toolpaths are not implemented. Machine-specific export and validation remain deferred; these files are not approved manufacturing instructions.

The document-export update passes 132 native core tests, five browser engine regressions and updated Windows compilation. All seven browser document buttons create actual downloads without native path prompts or unhandled page errors. Independent parsers confirm the complete 78-frame schedule, 90 native cutting rows, 70 native estimate terms, reference totals, fractional Excel dimensions, populated hardware/gasket/panel/glazing-bead/BOM sections and actual label identifiers. Every character is inside its PDF page; all 48 native/browser pages have been visually reviewed. New quotation drafts calculate the current project reference estimate instead of creating an empty zero-value record. Status changes and valid revisions persist; invalid amounts preserve existing data. The estimate PDF uses current project values, not a manually revised quotation total.

Workshop and production documents currently accept rectangular grid frames without extensions. PDF text supports the embedded font's Latin, Greek and Cyrillic coverage; unsupported characters produce an explicit error. Estimates use the supplied reference cost table in EUR, with project discounts, installation, transport and tax. They require local supplier/commercial validation. Frame development requires Rust 1.88 or newer because of its locked dependencies; this audit uses Rust 1.98.
